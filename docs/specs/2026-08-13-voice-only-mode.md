# Voice-Only Mode — ตัดโหมดพิมพ์ออกจาก flow ปกติ

วันที่: 2026-08-13
สถานะ: design (ยังไม่ implement)

## เป้าหมาย

ให้การฝึกซักประวัติสะท้อนสถานการณ์จริงที่ร้านยา — เภสัชกรกับผู้ป่วย**คุยกันด้วยเสียง ไม่มีบทให้อ่าน**

สองการเปลี่ยนแปลง:
1. โหมดพิมพ์หายจาก UI ปกติ เหลือไว้เป็นโหมดฉุกเฉินที่โผล่เองเมื่อเสียงใช้ไม่ได้จริง
2. ฟองแชทระหว่างคุยถูกซ่อนจากผู้เรียน (ยังบันทึกลง `/sessions` ครบ) ทีมงานดูได้ในหน้า admin

## ที่มา

พบระหว่าง audit voice mode (2026-08-13) ว่า:

- โมเดล native audio **กินเสียงตรงๆ** ส่วน `inputAudioTranscription` เป็น ASR อีกสายที่วิ่งขนานกัน สองสายไม่ตรงกันได้ ผู้เรียนจึงเห็นข้อความตัวเองเพี้ยน (บางครั้งกลายเป็นภาษาลาว/เขมร) ทั้งที่ผู้ป่วยเข้าใจถูกและตอบถูก → **ฟองแชทเป็นตัวสร้างความสับสน ไม่ใช่ตัวช่วย**
- public API **ไม่มีทางล็อกภาษา** ของ transcription (`AudioTranscriptionConfig` ไม่มี field ใดๆ) แก้ที่ต้นเหตุไม่ได้
- โหมดพิมพ์กับโหมดเสียงใช้คนละโมเดล (`gemini-2.5-flash` vs `gemini-3.1-flash-live-preview`) ผู้เรียนที่เลือกคนละโหมดจึงได้ intervention ไม่เหมือนกัน — กระทบ treatment fidelity

## ขอบเขต

**อยู่ในขอบเขต:** ซ่อน UI โหมดพิมพ์ · ซ่อนฟองแชท · บันไดสำรอง 3 ขั้น · บันทึกการลดระดับ · หน้าดู transcript ใน admin

**ไม่อยู่ในขอบเขต:** แยก `chat.js` (Phase 2 — refactor ใหญ่ไม่ควรปนกับ feature change ก่อนเก็บข้อมูล) · CSV export (Phase 1 แยกอยู่แล้ว) · เล่นเสียงย้อนหลัง · ค้นหา/ฟิลเตอร์ใน transcript viewer · แนบเสียงจริงไปให้ตัวประเมิน

## การตัดสินใจที่เคาะแล้ว

| ประเด็น | ผล | เหตุผล |
|---|---|---|
| โหมดพิมพ์ | เก็บไว้เป็นโหมดฉุกเฉิน ไม่ลบ | ถ้า Live ล่มกลางการเก็บข้อมูล ต้องยังทำเคสต่อได้ |
| วิธีเปิดโหมดฉุกเฉิน | โผล่เองเมื่อเสียงล้มจริง | ไม่มีทางเลือกกดเอง = ไม่มีทางเลี่ยงเสียงเพื่อความสะดวก |
| ซ่อนอะไร | ซ่อนฟองแชท เก็บซับไตเติล | ซับไตเติลแสดงเฉพาะคำพูดผู้ป่วย → ผู้เรียนไม่มีวันเห็นคำพูดตัวเองที่ถอดเพี้ยน แต่ยังมีตัวช่วยฟัง |
| log ของทีม | สร้างหน้าดู transcript ใน admin | ปัจจุบัน `admin.js` ไม่เคยแตะ `/sessions` เลย ทีมต้องเปิด Firebase Console |
| นาฬิกาตอนระบบล่ม | ไม่หยุด แต่บันทึก `degraded` | หยุดนาฬิกาเพิ่ม state และเปิดช่องถ่วงเวลา · แก้ที่ปลายทางดีกว่า (ทีมเห็น flag แล้วให้ทำใหม่ โควต้ามี 5 ครั้ง/วัน) |
| แนวทาง implement | flag เดียว ซ่อนด้วย CSS | diff เล็ก ย้อนกลับได้ด้วยการพลิกค่าเดียว และโหมดฉุกเฉินใช้เส้นทางโค้ดเดิมที่ผ่านการใช้งานจริงมาแล้ว |

## สถาปัตยกรรม

### จุดควบคุมเดียว

```js
const VOICE_ONLY = true;   // js/screens/chat.js
```

ทุกพฤติกรรมด้านล่างอ่านค่านี้ พลิกเป็น `false` → แอปกลับไปเหมือนเดิมทุกประการ (ทางถอยที่ไม่ต้อง revert commit กลางการเก็บข้อมูล)

### สิ่งที่ซ่อน — ซ่อนด้วยคลาส ไม่ลบ DOM

| องค์ประกอบ | เดิม | ใหม่ |
|---|---|---|
| `.mode-switcher` (แท็บ 🎙️/💬) | เห็น | ไม่เรนเดอร์ |
| `.transcript-wrap` → `.chat-messages` | เห็นฟองแชท | ซ่อน (DOM ครบ) |
| `#text-input-row-{1,3}` | สลับได้ | ซ่อน |
| `.tts-check` "อ่านเสียง" | โผล่ในโหมดพิมพ์ | ไม่เรนเดอร์ |
| ซับไตเติล · orb/ตัวละคร · นาฬิกา · ปุ่มขั้นตอน | เห็น | ไม่แตะ |

**"ไม่เรนเดอร์" กับ "ซ่อน" ต่างกันโดยตั้งใจ:**
- **ซ่อนแต่เก็บ DOM** = `.chat-messages` และ `#text-input-row-N` — โหมดฉุกเฉินต้องเรียกกลับมาใช้ แค่ถอดคลาส `hidden` ออก บทสนทนาที่ผ่านมาโผล่ครบทันที ไม่ต้อง render ย้อนหลัง
- **ไม่เรนเดอร์เลย** = `.mode-switcher` และ `.tts-check` — ไม่มีวันได้ใช้อีก เพราะโหมดฉุกเฉินเข้าเองอัตโนมัติ ไม่มีการสลับโหมดด้วยมือ

`_addMsg()` **ไม่แก้เลย** — ยัง push เข้า `_chatHistory` และเขียนลง DOM เหมือนเดิม แค่ container ถูกซ่อน

### ช่องแจ้งเตือน — `_notify()`

ปัญหา: ข้อความ system (`⚠️ Live API ไม่พร้อมใช้` ฯลฯ) ปัจจุบันขึ้นเป็นฟองแชท (`chat.js:547,567,580,621`) พอซ่อนฟองแชท **ผู้เรียนจะไม่รู้ว่าระบบมีปัญหา** เห็นแค่ผู้ป่วยเงียบไป

แก้: เพิ่ม element ถาวร `#voice-notice-{panelStep}` ใต้เวทีเสียง และฟังก์ชัน

```js
_notify(panelStep, msg)   // เขียนลง #voice-notice-N (ผู้ใช้เห็น) + _addMsg(...,'system',...) (ลง log)
```

เปลี่ยนจุดที่เรียก `_addMsg(..., 'system', ...)` ทั้ง 4 จุดมาใช้ `_notify` แทน

**ทำไมไม่ใช้ `_setVoiceStatus()` ที่มีอยู่** — มันถูก `onStateChange` เขียนทับตลอด (`connecting`/`listening`/`ai-speaking`) ข้อความเตือนจะหายในไม่กี่วินาที

## บันไดสำรอง

```
L0  Live API ─────── ปกติ (ไม่มีฟองแชท มีซับไตเติล)
      │ ต่อไม่ติด / error กลางคัน
      ▼
L1  Web Speech ───── ยังเป็นเสียง (ไม่มีฟองแชท) ผู้ป่วยตอบผ่าน geminiChat + TTS
      │ เบราว์เซอร์ไม่รองรับ / ไมค์ถูกปฏิเสธ
      ▼
L2  โหมดพิมพ์ฉุกเฉิน ─ ฟองแชท + ช่องพิมพ์โผล่ พร้อมคำอธิบาย
```

### กฎการเปลี่ยนระดับ — ฟังก์ชันบริสุทธิ์

แยกการตัดสินใจออกจาก DOM เพื่อให้ทดสอบใน Node ได้:

```js
_nextLevel(current, failureKind) -> nextLevel
```

| `failureKind` | จาก | ไป |
|---|---|---|
| `mic-denied` | L0 | **L2** (ข้าม L1) |
| `live-connect-failed` | L0 | L1 |
| `live-runtime-error` | L0 | L1 |
| `no-speech-api` | L1 | L2 |
| `speech-not-allowed` | L1 | L2 |
| `no-speech` / `network` | ใดๆ | คงเดิม (ชั่วคราว) |

**`mic-denied` ข้าม L1** เพราะ Web Speech ใช้ไมค์ตัวเดียวกัน ลองไปก็ล้มซ้ำ เสียเวลาผู้เรียนเปล่า

### ลงแล้วไม่ขึ้น

ตั้ง `_emergencyText = true` ระดับเซสชัน · `_startVoice()` เช็คแล้ว return ทันที
ถ้าตกลง L2 ตอน Step 1 → Step 3 อยู่ L2 ต่อ ไม่เด้งกลับเป็นเสียงกลางคัน

### L1 ต้องไม่เงียบสนิท

ใน Web Speech ผู้ป่วยตอบผ่าน `_sendChat()` → `_addMsg()` → ฟองแชท (ซ่อนแล้ว) + TTS
ซับไตเติลไม่ถูกป้อนเพราะรับจาก `onPartialModelTranscript` ของ Live เท่านั้น
→ ให้ `_sendChat()` / `_sendCounseling()` เขียนคำตอบลงซับไตเติลด้วยเมื่อ `VOICE_ONLY`

**ที่ L2 ไม่ต้องป้อนซับไตเติล** — ฟองแชทถูกเปิดกลับมาแล้ว ผู้เรียนอ่านจากฟองได้ตามปกติ
(เงื่อนไขคือ `VOICE_ONLY && !_emergencyText`)

### บันทึกการลดระดับ

เพิ่มใน `db.js`:

```js
markSessionDegraded(sessionId, level, reason)
// เขียน degraded: { level: 'L1'|'L2', reason: <failureKind>, at: serverTimestamp() } ลง /sessions
```

เรียกทุกครั้งที่เปลี่ยนระดับ **เขียนทับด้วยระดับล่าสุด** (L0→L1→L2 จบด้วย `level: 'L2'`)
ไม่เก็บประวัติการไล่ระดับ เพราะสิ่งที่ทีมต้องรู้คือเซสชันนี้จบที่ระดับไหน

เขียนจากฝั่งผู้เรียนตอนเกิดเหตุ — `firestore.rules:56` อนุญาต update session ที่ `userId` ตรงกับตัวเองอยู่แล้ว
**ไม่ต้องแก้ rules**

ทีมแยกออกว่าเคสไหนเจอปัญหาเทคนิค ไม่ใช่ผู้เรียนทำไม่ได้ — สำคัญตอนตีความข้อมูล
และเนื่องจาก L1/L2 ใช้โมเดลข้อความ field นี้จึงเป็น **บันทึก treatment fidelity ในตัว**

## หน้าดู transcript (admin)

**ไม่สร้าง route ใหม่** — `admin.js:1102` คลิกผลการประเมินไป `Router.go('summary', { resultId })` อยู่แล้ว
เพิ่มบล็อกพับได้ท้ายหน้า `summary`: `🗂️ บทสนทนาเต็ม (เฉพาะทีมงาน)`

**กันนักศึกษาเห็น 2 ชั้น** — `firestore.rules:53` อนุญาตให้นักศึกษาอ่าน session **ของตัวเอง** ได้ ถ้าเรนเดอร์ให้ทุกคนจะรั่ว
1. ไม่เรียก `getSessionById()` ถ้า `!isAdmin()` (ไม่ดึงข้อมูลตั้งแต่แรก)
2. ไม่เรนเดอร์บล็อกถ้า `!isAdmin()`

**สิ่งที่แสดง**

| ส่วน | รายละเอียด |
|---|---|
| สรุปหัวบล็อก | จำนวนเทิร์นแยกตาม `via` เช่น `live 12 · webspeech 0 · text 0` |
| แถบเตือน | ถ้ามี `degraded` → `⚠️ ลดระดับเป็น L2 เพราะ mic-denied เมื่อ 14:32` |
| Step 1 | บทสนทนาซักประวัติ ทุกเทิร์นมี badge `via` และ `…` ของเทิร์นที่ถูกพูดแทรก |
| ยาที่จ่าย | `dispensedDrugs` |
| Step 3 | บทสนทนา counseling รูปแบบเดียวกัน |

ทุกค่าจากผู้ใช้ผ่าน `escapeHtmlBr()` ตามกติกาโปรเจกต์

ไม่ต้องแก้ `firestore.rules` (admin อ่าน `/sessions` ได้อยู่แล้ว) และไม่ต้องเพิ่ม query helper (`db.js:124` มี `getSessionById()`)

## การทดสอบ

**ปัญหาหลัก: โหมดฉุกเฉินจะไม่ถูกใช้จนกว่าจะเกิดเหตุจริง** — โค้ดที่ไม่เคยรันคือโค้ดที่พัง

1. **Unit (`node:test` ต่อท้ายชุด 80 เทสต์ใน `setup/`)** — ตาราง `_nextLevel()` ทุกแถว · `markSessionDegraded()` เขียน field ถูก
2. **Smoke (Node)** — รันฮาร์เนสดัก-แล้ว-replay setup payload ซ้ำ ยืนยันว่า Live ยังต่อติดหลังแก้
3. **Playwright** — เขียน `tests/specs/04-voice-ui.spec.js` ใหม่ (ปัจจุบัน fail): ไม่มีแท็บสลับโหมด · `.chat-messages` ถูกซ่อน · ซับไตเติลยังอยู่ · บังคับ L2 แล้วฟองแชท+ช่องพิมพ์โผล่พร้อมข้อความแจ้ง (DOM ล้วน ไม่ต้องใช้ไมค์)
4. **Manual (ต้องมีคนพูด)** — คุยจบเคสจริง 1 รอบ · ปฏิเสธสิทธิ์ไมค์ → ต้องลง L2 ทันที · ตัดเน็ตกลางคัน → ต้องเห็นข้อความเตือน ไม่ใช่เงียบหาย

## ลำดับปล่อย — เรียงตามความเสี่ยงน้อยไปมาก

1. **หน้าดู transcript ใน admin** — แยกอิสระ ไม่แตะ flow นักศึกษา ปล่อยก่อนเพื่อให้ทีมมองเห็นข้อมูลก่อนพฤติกรรมเปลี่ยน
2. **`_notify()` + `#voice-notice-N`** — ยังไม่เปิด voice-only ข้อความ system ขึ้น 2 ที่
3. **`VOICE_ONLY = true` + ซ่อน UI**
4. **บันไดสำรอง + `degraded`**
5. **Freeze** — ตั้ง `VOICE_ONLY` เป็นค่าสุดท้าย ห้ามแก้ prompt/rubric/flag ระหว่างเก็บข้อมูล (ต่อยอดวินัย `GROUNDING_VERSION`)

## ความเสี่ยงที่รับรู้แล้ว

- **ผู้เรียนที่มีปัญหาการได้ยิน หรืออยู่ในที่เสียงดัง** จะเสียเปรียบ — ยอมรับได้เพราะทักษะที่วัดคือการซักประวัติด้วยการพูด และซับไตเติลผู้ป่วยยังอยู่
